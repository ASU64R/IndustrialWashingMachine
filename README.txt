## Суть проекта
Модель стиральной машины. Полный цикл: залить воду до 30% → нагреть до уставке рецепта → стирать/полоскать барабаном → слить → отжать. 4 зоны + мастер, который гоняет цикл по рецепту.

Проект, второй по счёту. Цель — не «чтобы крутилось», а собрать правильную архитектуру дискретного управления: машины состояний, аварии с квитированием, handshake мастер↔зоны, ручной арбитраж и защиту исполнительных механизмов. Синтаксис ST здесь средство, не цель.


- **PLC_PRG** — диспетчер: тянет входы с HMI/железа, HMI watchdog, вызывает FB по порядку
- **FB_MasterManager** — цикл стирки, раздача команд зонам, глобальная авария, история ошибок
- **FB_Zone** — локальная машина состояний своей зоны, отдаёт статусы мастеру
- **FB_Manual** — финальный арбитраж: manual / auto / safety override

## Режимы
- **AUTO** — цикл по рецепту, мастер гоняет зоны
- **MANUAL** — ручное управление, только когда мастер разрешает (Idle или Aborted для ремонта)
- **Stop** — graceful: зона доделывает текущее действие и встаёт в Complete
- **E-Stop** — рубит всё, включая аварийный слив

## Приоритеты защит (сверху вниз)
1. E-Stop / FireAlarm
2. Физические защиты (перелив HH, вибрация HH, перегрев, открытая дверь)
3. MANUAL
4. AUTO

## Defense in Depth
- Зоны — `ELSE → Aborted` + барьер по каждому выходу (не инверсия рабочего состояния)
- Мастер — `ELSE → Aborted` + глобальная авария из статусов зон
- PLC_PRG — HMI watchdog (2 сек): при потере связи гасит только manual-команды, авто цикл идёт дальше
- Аварийный слив — latch `HH → L`, держится пока не сольёт, E-Stop сбрасывает

## Диагностика
- **ActiveError** — текущая ошибка с приоритетами (ENUM)
- **История** — массив на 10 последних уникальных ошибок, без дублей
- **Fault / Warning** — Fault защёлкивается (нужен Reset), Warning сбрасывается сам

## Ключевые принципы
-  Статусы мастеру — только после CASE, одной формулой. CASE не пишет `stStateStatus.*`
-  Барьер = список запрещённых состояний для каждого выхода. Насос-лекарь живёт в Aborted, мотор — нет
-  Safety override не всегда FALSE: перелив закрывает клапаны, но включает сливной насос
-  Выход с памятью (ТЭН-гистерезис) не сбрасывается перед CASE — иначе гистерезис умирает
-  FirstCycle трогает только состояние, не выходы. Выходом владеет цикл
-  `VAR` = состояние между сканами (latch), `VAR_TEMP` = расчёт одного скана
-  Разделение ответственности: зоны не знают про HMI, мастер не знает про железо

## Особенности
- MANUAL не блокируется защёлкнутыми авариями — можно тестить зону после устранения причины
- Abort/Reset от мастера к зонам — импульсы, поэтому порядок вызова `Master → зоны` критичен (зафиксирован в PLC_PRG)
- Защита сливного насоса от сухого хода не делал — нет в ТЗ
- ТЭН гасится при аварийном сливе — процесс уже не штатный

**Стандарты:** IEC 61131-3, State Machine, Defense in Depth
